# 用户需求（Agent 每次运行前必读）

> 这是唯一需要你自己填的文件，放在 `~/.moodle-killer/user_requirements.md`。
> 脚本负责：抓取、通用噪音过滤、关键词打桶、校验（人人一样）。
> 本文件负责：你的个性化判断规则（Agent 读了执行）。改需求只改这里，不动脚本。
>
> **开始使用**：
> ```bash
> mkdir -p ~/.moodle-killer
> cp user_requirements.example.md ~/.moodle-killer/user_requirements.md
> ```
> 然后按下面的示例改成你自己的课程和规则。

## Moodle 规则

### 提醒优先级
- **Project / Exam 类作业**：只要未提交，每次推送都必须带倒计时（用脚本信号里算好的剩余时间，精确到小时和分钟），格式醒目：`[新作业] 课程: 名称 截止 M/D HH:MM (剩X天Y小时Z分)`
- 已提交的作业不提醒截止；但出现**成绩/评语**时用 [成绩] 推。
- 通知只看**近 24 小时内**的新通知，过期跳过。

### 课程专属（示例，改成你自己的）
- **<课程A>**：Project/Exam 倒计时保持醒目（🔴 前缀）。
- **<课程B>**：只关注文件更新；名称含 `<某关键词>` 的任何东西一律忽略。
- **<课程C>**：新下载的文件按文件名归类。

> 某门课完全不想收 → 用 `mk mute <课程名>`，不用写在这里。

### 文件归类
脚本默认**每门课一个文件夹**（`~/School/<课程名>/`）。
想让课内再按类型分（`Assignment/`、`Slides/`、`Textbook/`、`Other/`）：

```bash
mk set --advanced              # 看高级项
mk set 按类型 true             # 打开按类型分文件夹
```

类型关键词表在 `~/.moodle-killer/config.yaml` 的 `download.type_map`，想加自己的词就改那里。

## 兜底判断（未命中关键词时才执行）

- 脚本已过滤通用噪音与**时效性即时类**（验证码/登录码——分钟级过期，隔日摘要无价值；邀请确认类——当场已处理）。
- 你判断的是**兜底队列**（`~/.moodle-killer/out/unclassified_moodle.json`），按两条原则：
  - **值得推**：有未来行动点的学业信息（作业、成绩、截止、日程变动）——即「明天早上看到仍有用」的
  - **丢弃**：时效性当场类、同名/非本人误报、营销/广告——即「看到时已经没用了」的
  - **拿不准就不推**
- 不要重复脚本已经输出的条目（看 `out/signals.txt`）。

## 输出心跳

- 无新内容时怎么表现由 `output.mode` 决定（`heartbeat` 报一句、`silent`/`urgent` 不说话）。
- 校验失败（`❌`）必须原样透出，不得吞掉。静默 ≠ 故障。

## 输出格式

- ≤5 行纯信号，格式 `[新作业|新文件|成绩|公告] 课程: 内容 [+ 截止]`，零寒暄零空行。
