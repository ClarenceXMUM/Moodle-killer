# Notification Agent Skill

> 把「Moodle 课程通知 → 高密度摘要推送」封装成**框架无关**的便携 Skill。
> 目标：任意本地 Agent / Agent 框架 / 办公智能体都能跑。
> 核心架构：**关键词优先（脚本，零 LLM）→ 未命中兜底（Agent）＋ 每一步验证**。

---

## 何时使用

用户需要「按时抓取某个站点的通知，压缩成 3–5 行高密度推送」时使用。本 Skill 以 Moodle 课程通知为第一用例，但架构可迁移到任意通知源。

## 不做什么

- 不做复杂语义理解（那些交给 Agent 兜底层）。
- 不依赖任何特定 Agent 框架的内部 API——只用通用原语（读/执行/写文件/浏览器/电脑操作）。

---

## 核心思想（一句话）

**脚本先扛，Agent 兜底。** 能靠关键词规则命中的通知，脚本直接出固定信号（不花 token、不超时）；命中不了的，才让 Agent 去读这条消息到底是什么。**每一步动作都要有验证**，否则推送就是赌运气。

---

## 流程

```
[定时触发]
  └─ moodle_prep.py     抓取 Moodle + 关键词打桶，带登录态校验
                          ├─命中──▶ 出固定信号
                          └─未命中──▶ Agent 兜底：读消息→判断→表达
  └─ verify.py          四步验证：登录✅ / 抓全✅ / 下载落地✅ / 课程扫全✅
  └─ 输出 3–5 行高密度推送
```

---

## 关键词规则（classify.py 配置，可扩展）

| 桶 | 触发关键词（中文/英文） | 固定信号模板 |
|----|------------------------|------------|
| 新作业 | `assignment`, `作业`, `due`, `deadline`, `submit` | `[新作业] <课程>: <标题> 截止 <日期>` |
| 成绩 | `grade`, `score`, `成绩`, `feedback`, `评语` | `[成绩] <课程>: <分数/评语>` |
| 公告 | `announcement`, `公告`, `notice`, `通知` | `[公告] <课程>: <标题>` |
| 下载 | `file`, `download`, `附件`, `resource` | `[附件] <课程>: <文件> 已下载` |

- 命中 → 直接出模板，**零 LLM**。
- 未命中 → 打 `UNCLASSIFIED` 桶，交给 Agent 兜底。

---

## 兜底 Agent 细则（未命中关键词时才执行）

当脚本无法判断这条信息是什么：

1. **读出原文**：用 `read` / `browser` / `计算机操作` 把这则通知的正文完整抓到。
2. **判断要点**：它是否值得推给用户？(新信息 vs 老信息、是否影响用户行动)。
3. **表达**：压缩成 3–5 行，每行 = 标题字段 + 值，无寒暄无空行。
4. **不确定就不推**：宁可漏提，不推模糊噪音。

---

## 输出契约（硬规定）

- 单次推送 = **3–5 行**，超 5 行视为失败重写。
- 每行格式：`[类型] 字段: 值`（如 `[新作业] 数学分析: 第4章练习 截止 9/20`）。
- **零寒暄、零空行堆砌**；空行只作信号块分隔。
- 留白准则：留白只有两条路——**激起兴趣（有用）** 或 **什么都没发生（浪费）**。达不到前者就删。

---

## 验证清单（verify.py，产品视角硬要求）

每步都验证，缺一不可：

- [ ] **登录成功**：能确认已进入登录后状态（`已登录` / 账号名出现 / 非 login 页）。
- [ ] **抓取完整**：通知页每条信息都抓到（对比页面条目计数 == 入库计数）。
- [ ] **下载落地**：下载页真的把文件写到了磁盘（文件存在 + 大小 > 0）。
- [ ] **课程扫全**：本学期每个课程都扫过（课程清单与抓取结果逐一对账，缺课要报错）。
- [ ] **推送行数**：输出 ≤ 5 行；超限即重写。

---

## 定时任务建立

任意框架的 cron / 调度器，每天固定窗口触发 `scripts/run_pipeline.sh`：

```bash
# 每天 08:30 触发（示例；时间窗口按用户查阅节奏调）
30 8 * * * cd <this-repo> && ./scripts/run_pipeline.sh
```

`run_pipeline.sh` 串联：`moodle_prep.py`（抓取 → 打桶 → 校验）→ 兜底 agent → 推送。框架无关。

---

## 可移植性要求

- `SKILL.md` 只用通用 agent 原语（读取、执行、写文件、浏览器、电脑/Computer Use 操作），**不引用 Hermes 内部 API**。
- 脚本只用 Python 标准库 + 通用 CLI；凭据从环境变量 / `.env` 读，不上传。
- 任意 Agent 框架满足上述原语即可接入。

---

## 目录结构

```
Moodle-killer/
  docs/AGENT-SKILL.md      # 本文件（细则 + 关键词规则 + 验证清单 + 输出契约）
  scripts/
    run_pipeline.sh        # 串联：moodle_prep.py → 兜底 agent → 推送
    moodle_prep.py         # Moodle 抓取 + 关键词打桶 + 四步校验
    moodle_client.py       # Moodle HTTP 客户端（登录/通知/扫课/下载）
    setup_moodle.py        # 课程发现 + 生成 courses.json
    classify.py            # 通用关键词打桶，命中即出固定信号，不调 LLM
    verify.py              # 四步校验（登录/抓全/下载/课程对账）+ 行数校验
    appconfig.py           # 配置加载器（config.yaml → env → 默认值）
    sender.py              # 发送模块（telegram/webhook/whatsapp）
  config.example.yaml      # 配置模板（不提交真实值）
  requirements.txt
  README.md                # 部署到任意 agent / 办公智能体说明
```
